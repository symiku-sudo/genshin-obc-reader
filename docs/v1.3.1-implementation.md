# 1.3.1 实现与验证

## 已确定范围

- GitHub Releases 应用更新：启动后每日最多一次静默检查、管理页手动检查、版本/说明/大小展示、用户主动下载、下载进度、暂停与跨进程续传、官方发布页后备入口。
- 安装前核对 SHA-256、包名、版本号和签名；通过系统安装器由用户确认覆盖安装。
- “我的划线”改为全屏页面，默认全部、创建时间倒序。仅分类筛选和单关键词搜索（原文、笔记、来源标题），保留编辑/删除/原文跳转以及返回时的筛选和滚动位置。
- 不包括其他待办、文本库扩充、剧透处理、多关键词搜索、逐来源下拉、是否有笔记筛选。

## 实现要点

- 原有划线 ID、正文位置和本地存储不迁移。新划线附带分类；旧划线从仅含 ID/标题/分类的 SQLite 索引补齐展示。找不到来源时归入“未分类”。
- 每次展示最多增加 50 条，搜索直接覆盖全部划线。空格作为关键词的一部分，不拆词。
- 更新由独立后台线程执行，不阻塞正文 API。下载保存在应用私有目录；退出或断网后可主动继续。
- 每次继续下载先获取最新发布信息。安装包资产 ID、哈希或大小变化时丢弃旧前缀；服务端忽略 Range 时从头覆盖；响应区间不符时拒绝追加。
- 下载完成、启动系统安装器前分别校验。仅接受正式稳定版本与本仓库指定文件名的 APK。FileProvider 只共享 updates 子目录。
- 自动检查失败不打断阅读；手动操作显示错误并提供重试和浏览器入口。不会自动下载或安装。后台运行受 Android 生命周期约束，进程退出后保留文件，重新打开后点击继续下载。
- 不修改 release.json，不自动发布正式版本。
